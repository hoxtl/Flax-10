\chapter{Overview}

StudyFlax is a web-based academic time management platform built for
students and teachers at King's College London. It allows students to
organise their schedules, track deadlines, and manage their academic
workload in one place. Teachers can create modules, set deadlines, and
assign work to their students, whilst the admin oversees and manages
the system as a whole.

The system consists of two software components:

\begin{itemize}
    \item \textbf{Backend} --- A Django (Python 3.14) REST API backed
          by a PostgreSQL database.
    \item \textbf{Frontend} --- A React (Vite) single-page application.
\end{itemize}

The deployed application is available at:
\url{https://flax-10-production.up.railway.app/}

\chapter{Setting Up the Development Environment with Nix}

This project uses a Nix flake to automate the full development
environment setup. Upon entering the Nix shell, the following steps
are performed automatically:

\begin{itemize}
    \item A Python 3.14 virtual environment is created and activated.
    \item All Python dependencies are installed from
          \texttt{requirements.txt}.
    \item All Node.js (v20) dependencies are installed via npm.
    \item Django database migrations are applied
          (\texttt{makemigrations} and \texttt{migrate}).
    \item The database is seeded with fixture and generated data.
    \item The Django development server is started on
          \texttt{http://localhost:8000}.
    \item The Vite frontend development server is started.
    \item Backend and frontend coverage reports are generated.
\end{itemize}

\section{Linux and macOS}

\begin{enumerate}
    \item Navigate to the root of the repository:
\begin{lstlisting}[language=bash]
cd /path/to/Flax-10
\end{lstlisting}

    \item Enter the Nix development shell:
\begin{lstlisting}[language=bash]
nix --extra-experimental-features 'nix-command flakes' develop -c bash
\end{lstlisting}

    \item \textbf{Optional --- enable experimental features permanently.}
          Add the following line to \texttt{/etc/nix/nix.conf} to avoid
          passing the flags on every invocation:
\begin{lstlisting}
experimental-features = nix-command flakes
\end{lstlisting}

    \item On first run, the flake creates the virtual environment and
          installs all dependencies. On subsequent runs, it detects the
          existing environment and activates it. You will be returned to
          a \texttt{bash} terminal once setup is complete.
\end{enumerate}

\section{Windows (via Docker Desktop)}

On Windows, Nix is run inside a Docker container using the official
NixOS image.

\begin{enumerate}
    \item Open the Docker Desktop terminal.

    \item Navigate to the repository folder:
\begin{lstlisting}[language=bash]
cd \path\to\Flax-10
\end{lstlisting}

    \item Create a persistent Nix store volume:
\begin{lstlisting}[language=bash]
docker volume create nix-store
\end{lstlisting}

    \item Launch the NixOS container. In PowerShell, use a backtick
          (\texttt{`}) for line continuation:
\begin{lstlisting}[language=bash]
docker run --rm -it `
    -v "${PWD}:/work" `
    -v nix-store:/nix `
    -w /work `
    nixos/nix:latest
\end{lstlisting}

          If the above does not work, use the single-line version:
\begin{lstlisting}[language=bash]
docker run --rm -it -v "${PWD}:/work" -v nix-store:/nix -w /work nixos/nix:latest
\end{lstlisting}

    \item Inside the NixOS container, stage the flake file:
\begin{lstlisting}[language=bash]
git -C "/work" add "flake.nix"
\end{lstlisting}

    \item Enter the Nix development shell:
\begin{lstlisting}[language=bash]
nix --extra-experimental-features 'nix-command flakes' develop -c bash
\end{lstlisting}

    \item The container is configured with \texttt{--rm} and will be
          destroyed upon exit. Repeat steps 4--6 for each subsequent
          session.
\end{enumerate}

\section{Re-entering the Nix Shell in Future Sessions}

Each time you wish to return to the development environment, run the
following from the root of the repository:

\begin{lstlisting}[language=bash]
nix --extra-experimental-features 'nix-command flakes' develop -c bash
\end{lstlisting}

\chapter{Database Setup}

\section{Automated Setup via Nix (Recommended)}

The Nix shell hook runs \texttt{makemigrations}, \texttt{migrate}, and
\texttt{seed} automatically on entry. No manual database configuration
is required when using Nix.

\section{Manual PostgreSQL Setup}

If you are setting up the project without Nix:

\begin{enumerate}
    \item Install PostgreSQL and open the \texttt{psql} terminal.

    \item Accept all default connection parameters (server, database,
          port) by pressing \texttt{Enter} at each prompt.

    \item When prompted for a password, enter \texttt{1234} --- this
          is the default value expected by \texttt{settings.py}.

    \item Apply migrations and seed the database from within
          \texttt{flax-10-project-files/backend}:
\begin{lstlisting}[language=bash]
python manage.py makemigrations
python manage.py migrate
python manage.py seed
\end{lstlisting}
\end{enumerate}

\textbf{Note:} If you choose a different PostgreSQL password, update
the \texttt{PASSWORD} field in \texttt{settings.py} accordingly.

\chapter{Running the Application}

\section{Backend (Django)}

From within \texttt{flax-10-project-files/backend}:

\begin{lstlisting}[language=bash]
python manage.py runserver
\end{lstlisting}

The API will be available at \texttt{http://localhost:8000}.

\section{Frontend (React / Vite)}

From within \texttt{flax-10-project-files/frontend}:

\begin{lstlisting}[language=bash]
npm run dev
\end{lstlisting}

The frontend will be available at \texttt{http://localhost:5173}
(or the port shown in the Vite terminal output).

\textbf{Note:} When using the Nix shell, both servers are started
automatically in the background.

\chapter{Running the Tests}

\section{Backend Tests and Coverage}

From within \texttt{flax-10-project-files/backend}:

\begin{lstlisting}[language=bash]
python -m coverage erase
python -m coverage run manage.py test
python -m coverage report -m
python -m coverage html
\end{lstlisting}

The HTML coverage report is generated at\\
\texttt{flax-10-project-files/backend/htmlcov/index.html}.

\textbf{Note:} The Nix shell runs these commands automatically on entry.

\section{Frontend Tests and Coverage}

From within \texttt{flax-10-project-files/frontend}:

\begin{lstlisting}[language=bash]
npm run test -- --run
npm run coverage
\end{lstlisting}

\chapter{Troubleshooting}

\begin{description}

    \item[Nix experimental features error.]
    If you encounter an error relating to \texttt{nix-command} or
    \texttt{flakes}, ensure the flags are passed as shown in
    Chapter~4, or add them permanently to \texttt{/etc/nix/nix.conf}.

    \item[Database connection error.]
    Verify that your PostgreSQL server is running and that the password
    in \texttt{settings.py} matches your local PostgreSQL password
    (default: \texttt{1234}).

    \item[Port already in use.]
    If \texttt{localhost:8000} or \texttt{localhost:5173} is already
    occupied, terminate the conflicting process or start the server
    on an alternative port:
\begin{lstlisting}[language=bash]
python manage.py runserver 8080
\end{lstlisting}

    \item[Coverage module not found.]
    Ensure \texttt{coverage} is installed in the virtual environment:
\begin{lstlisting}[language=bash]
pip install coverage
\end{lstlisting}

    \item[Windows Docker container exits immediately.]
    Ensure Docker Desktop is running and that the \texttt{nix-store}
    volume has been created before executing the \texttt{docker run}
    command.

    \item[Re-seeding inflates data.]
    The Nix shell runs \texttt{python manage.py seed} on every entry,
    which may duplicate seeded data. To reset the database to a clean
    state, run the following from within
    \texttt{flax-10-project-files/backend}:
\begin{lstlisting}[language=bash]
python manage.py flush --no-input
python manage.py migrate
python manage.py seed
\end{lstlisting}

\end{description}
